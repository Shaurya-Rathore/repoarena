# ADR: cloud core boundaries

Status: accepted, 2026-09-01.

RepoArena cloud core uses PostgreSQL as the sole production system of record.
Forward-only SQL migrations own schema evolution; application startup never
auto-synchronizes schema. Application services authorize tenant resources before
data access and own transactions. HTTP handlers validate and translate DTOs but
do not contain the permission model or raw SQL.

Canonical execution results remain the execution engine's public-safe schemas.
Cloud storage persists those records rather than recalculating outcomes. Private
evaluator data has a separate table and service method and is never part of a
normal task or run DTO.

Artifact metadata lives in PostgreSQL while bytes use a provider-neutral object
store. Object keys are generated by the server. Durable jobs, leases, scheduler
occurrences, runner claims, and result completion are transactionally coordinated
in PostgreSQL. GitHub, Stripe, and the production cloud frontend remain outside
this boundary.
